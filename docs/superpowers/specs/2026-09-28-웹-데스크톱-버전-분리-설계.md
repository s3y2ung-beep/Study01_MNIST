# 웹 버전과 데스크톱 버전 분리 설계

작성일: 2026-09-28

## 요구

- 손글씨 인식 프로그램을 웹 버전과 데스크톱 버전으로 나누어 개발한다.
- 웹 버전은 외부 라이브러리 없이 순수 자바스크립트로 추론하고, GitHub Pages에 정적으로 올릴 수 있어야 한다.
- `web_version/`은 새로 작성하고, 기존 코드는 `desktop_version/`으로 옮긴다.
- 각 폴더에 해당하는 CLAUDE.md를 만든다.

## 결정 기록

### 1. 추론을 어디서 수행할까

| 대안 | 장점 | 단점 |
|---|---|---|
| 브라우저에서 순수 자바스크립트 (채택) | 서버가 필요 없어 GitHub Pages에 그대로 올라감. 요구 사항 그대로 | 순전파를 직접 다시 써야 함 |
| 브라우저에서 ONNX Runtime Web | 순전파를 쓸 필요 없음 | 외부 라이브러리라 요구 위반 |
| 파이썬 서버(Flask 등) | 기존 코드 재사용 | 정적 호스팅 불가 |

### 2. 학습과 변환을 어디에 둘까

학습은 기존 `train.py`를 그대로 쓰고, 가중치 내보내기 스크립트를 `desktop_version/`에 추가한다. 가중치의 출처가 파이썬 한 곳으로 유지된다.

### 3. GitHub Pages 배포를 범위에 넣을까

넣는다. `index.html`이 저장소 최상위가 아니라 `web_version/`에 있으므로, GitHub Actions 워크플로(`.github/workflows/pages.yml`)로 `web_version/`만 올린다.

### 4. 웹 버전 기능 범위

| 대안 | 장점 | 단점 |
|---|---|---|
| 데스크톱과 동일 + 터치 입력 (채택) | 두 버전을 나란히 비교하기 좋다. 만들 분량이 작다. 모바일에서도 쓸 수 있다 | 웹이라서 할 수 있는 것을 활용하지 않는다 |
| 28x28 전처리 미리보기 추가 | 전처리 단계를 눈으로 확인 | 두 버전이 완전히 같지 않게 된다 |
| 숫자 10개 확률을 모두 표시 | 헷갈리는 숫자를 한눈에 본다 | 화면이 길어진다 |

전처리 확인은 `검증.html`이 맡는다.

### 5. ONNX 변환 대신 무엇을 쓸까

ONNX를 쓰지 않는다. 층 4개의 weight와 bias를 float32 이진 파일로 내보내고, 순전파를 자바스크립트로 다시 쓴다.

### 6. "외부 라이브러리 없이"의 범위

실행 시 브라우저가 불러오는 코드에만 적용한다. 가중치 내보내기와 검증 데이터 생성은 이미 쓰는 파이썬 도구(PyTorch, Pillow, NumPy)로 한다. 빌드 도구와 테스트 프레임워크는 쓰지 않는다.

### 7. 정확성 검증 방법

파이썬 결과를 정답으로 두고 대조하는 `검증.html`을 만든다. 손으로 그려 보는 것은 마지막 확인으로만 쓴다.

### 8. 가중치 파일 형식

숫자 데이터는 `가중치.bin`(float32 이어 붙임), 이름과 형상과 정규화 상수는 `가중치정보.json`으로 나눈다. JSON 하나에 숫자 42만 개를 텍스트로 넣으면 파일이 3배 이상 커진다.

## 설계

### a) 폴더 구조 (태스크 1, 6)

```
study01_MNIST/
├── CLAUDE.md                 루트 안내 (두 버전의 관계)
├── README.md
├── .github/workflows/pages.yml
├── docs/superpowers/         설계 문서와 구현 계획
├── desktop_version/
│   ├── model.py  train.py  preprocess.py  app.py  손글씨인식.pyw
│   ├── mnist_cnn.pt
│   ├── 가중치내보내기.py      (추가)
│   ├── 검증데이터만들기.py    (추가)
│   └── CLAUDE.md
└── web_version/
    ├── index.html  스타일.css
    ├── 그림판.js  전처리.js  모델.js  앱.js
    ├── 검증.html
    ├── 가중치.bin  가중치정보.json
    └── CLAUDE.md
```

파일 이동은 `git mv`로 하여 커밋 이력을 유지한다.

### b) 데스크톱 버전 코드는 수정하지 않음 (태스크 1)

파이썬 파일은 옮기기만 한다. `train.py`는 상대 경로 `data`를 쓰므로 옮긴 뒤에는 `desktop_version/` 안에서 실행해야 한다. 이 사실은 코드를 고치지 않고 `desktop_version/CLAUDE.md`에 적는다.

### c) 가중치 내보내기 (태스크 2)

`가중치내보내기.py`가 `mnist_cnn.pt`를 읽어 두 파일을 만든다.

- `가중치.bin`: 층 4개의 weight와 bias(텐서 8개)를 float32 리틀 엔디언으로 이어 붙인 것 (파라미터 421,642개, 1,686,568바이트)
- `가중치정보.json`: 텐서별 이름, 형상, 시작 위치와 `preprocess.py`에서 읽은 정규화 상수 2개

### d) 자바스크립트 순전파와 전처리 (태스크 4, 5)

- `모델.js`: 합성곱(3x3, 덧대기 1) → ReLU → 2x2 최대 풀링을 2번, 전결합 → ReLU → 전결합 → 소프트맥스. 드롭아웃은 예측 때 아무 일도 하지 않으므로 생략.
- `전처리.js`: `preprocess.py`의 3단계를 그대로 옮긴다. PIL의 LANCZOS 축소는 브라우저에서 같게 재현할 수 없으므로 면적 평균 축소를 직접 구현한다. 정확도가 기준에 못 미치면 Lanczos를 구현한다.
- 반올림은 양쪽 모두 `floor(x + 0.5)`로 맞춘다.

### e) 검증과 성공 기준 (태스크 3, 4, 5)

`검증데이터만들기.py`가 MNIST 시험 이미지 200장을 앱과 같은 280x280으로 키운 그림, 파이썬 전처리 결과, 확률 10개, 정답 라벨을 `검증데이터.json`에 담는다(깃에 넣지 않음). 10배 최근접 확대만 쓰면 크기가 늘 10의 배수로 떨어지므로, 이 중 일부는 임의 배율과 위치, 부드러운 가장자리로 확대한다.

| 항목 | 기준 |
|---|---|
| 순전파 일치 | 같은 28x28 입력에 대한 확률의 최대 절대차 1e-4 이하 |
| 전체 정확도 | 200장 중 97% 이상 |
| 데스크톱 회귀 | 옮긴 뒤에도 파이썬 전처리와 추론 결과가 같음 |
| 웹 앱 동작 | 그린 숫자를 인식하고 상위 3개 후보 표시 |

### f) 웹 앱 화면 (태스크 6)

데스크톱과 같은 기능(280x280 그림판, 손을 떼면 인식, 상위 3개 후보, 지우기)에 터치 입력을 더한다. tkinter 코드는 브라우저에서 돌지 않으므로 화면 파일을 새로 쓴다.

### g) CLAUDE.md 3개 (태스크 7)

- 루트: 두 버전의 관계, 가중치 흐름, 공통 규칙
- `desktop_version/`: 기존 루트 CLAUDE.md 내용 + 가중치 내보내기와 검증 데이터 만들기
- `web_version/`: 로컬 실행법(`python -m http.server`, `file://`로는 안 됨), `가중치.bin` 형식, 파이썬과 맞춰야 할 지점, 검증 절차
